# STONE AWARDS 2026

Сайт премии в каменно-серой палитре с морскими стеклянно-зелёными акцентами. Есть вход по персональным кодам, главная страница с открытыми номинациями, голосование, результаты, секретные номинации и админ-панель.

## 1. Быстрый просмотр — демо

1. Распакуйте архив.
2. Откройте `index.html` в браузере.
3. Войдите как организатор: `STONE-ADMIN`.
4. Или как участник: `STONE-001` ... `STONE-013`.

В демо-режиме сайт сохраняет данные в localStorage только в текущем браузере. В стартовом наборе уже есть 20 новых номинаций и 13 номинантов. Коды демо-участников: `STONE-001` ... `STONE-013`. Это режим для проверки дизайна и функций, а не для общего голосования на разных устройствах.

## 2. Подключение настоящей общей базы

Для реального голосования всем участникам нужна общая база данных. В проекте используется Supabase.

1. Создайте проект на https://supabase.com/.
2. Откройте **SQL Editor** в панели Supabase.
3. Откройте файл `supabase/schema.sql`, скопируйте весь SQL и выполните его.
4. В Supabase откройте **Project Settings → API** и скопируйте:
   - Project URL
   - `anon` / publishable public key
5. Вставьте их в `config.js`:

```js
window.STONE_CONFIG = {
  supabaseUrl: "https://https://gmvjjhrfqlcsadugznrq.supabase.co",
  supabaseAnonKey: "sb_publishable_MD0dLy13x_9idtzu_uUk-Q_0lWtcctC"
};
```

Не используйте `service_role` key в браузере и не публикуйте его.

## 3. Создание администратора

1. В Supabase откройте **Authentication → Users**.
2. Создайте пользователя с email и паролем организатора.
3. В SQL Editor выполните запрос, заменив email на свой:

```sql
insert into public.admin_users(user_id)
select id from auth.users where email = 'ВАШ_EMAIL_ОРГАНИЗАТОРА'
on conflict do nothing;
```

4. На странице сайта нажмите «Вход для организатора» и используйте этот email и пароль.

## 4. Создание участников и запуск

1. Войдите в админ-панель.
2. Выполните `supabase/seed_nominees.sql`: скрипт создаст 20 номинаций и добавит 13 указанных номинантов (если их ещё нет в базе).
3. Передайте участникам коды, которые появятся в результате SQL-скрипта. Если участник уже был в базе, его прежний код продолжит работать.
4. Для остальных голосующих создайте отдельные учётные записи через админ-панель и передайте им коды лично.
5. Откройте нужные голосования в панели организатора.
6. Когда будете готовы, включите публикацию результатов.

Код участника хранится в базе в виде хеша. После входа создаётся отдельная сессия. Повторный голос в одной категории блокируется базой данных.

## 5. Публикация сайта

Можно загрузить папку проекта на статический хостинг, например Vercel или Netlify. Для Vercel:
1. Создайте GitHub-репозиторий и загрузите файлы проекта.
2. Импортируйте репозиторий в Vercel.
3. Выберите Framework Preset: **Other**.
4. Build Command оставьте пустой, Output Directory — `.`.
5. Разверните сайт.

Также можно использовать Netlify Drop для быстрой публикации статических файлов.

## Важно

- Сейчас это стартовая версия. В ней нет сброса голосов, редактирования/удаления номинаций и восстановления потерянных кодов.
- Один код предназначен для одного участника. Если участник передаст код другому человеку, тот сможет войти под его именем.
- Не публикуйте коды в общем чате.
- В демо-режиме данные локальные и не синхронизируются между устройствами.


### Смена кода существующего участника
В панели организатора найди участника и нажми «СМЕНИТЬ КОД ДОСТУПА». Подтверди действие и сразу скопируй показанный новый код. Старый код перестанет работать, активная сессия участника завершится, а уже записанные голоса и номинации сохранятся. Код хранится в базе в виде хеша и не может быть показан повторно.
